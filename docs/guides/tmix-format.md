# Verified SQLite observations and limits

All three supplied `.tmix` files are SQLite databases; `PRAGMA integrity_check` returned `ok`. Tables: config, cues, profiles, positions, ensembles, snippetCache, fxCache, sceneCache, actors, actorProfiles, actorGroups, sqlite_sequence. Clone a known-good schema rather than inventing DDL. The ensembles `channels` type contains the unusual text `TEXT\`channelProfiles\` TEXT`; preserve original schema.

Spring Chicken: 30 cues, 27 profiles, QL5, 12 controlled DCAs. Songs for a new world: 62 cues, six profiles, SQ-5, six DCAs. DNAHG ACT 1: 106 cues, 21 profiles, targetConsole SQ-7 while cached consoleModel is SQ-6; cached last-connected model is not proof of intended target. All config minVersion values are 3.0, profileSchemaVersion 2; that is a file observation, not proof of current app compatibility/version.

`cues` identity is number plus point; integer hundredths are corroborated by cue point 50/80 and provided notes. Spring Chicken has `skip`; the other two do not. Each has DCA01..12 columns even when six DCAs are selected. Inspect PRAGMA columns before inserting. DCA memberships are comma-separated channel integers, not profile IDs. Spring Chicken profile id17 maps to channel27; IDs and channels must remain distinct. Labels may be NULL/empty. Colour values need preservation on revisions; do not assign inferred semantics.

Position ID0 is the default record in every supplied working file, including Spring Chicken's Centre Stage. Blank cue channelPositions does not remove this requirement. A generated file containing only position1 crashed on opening in TheatreMix3.4.1. A one-change copy, altering only positions.id from1 to0, opened successfully as explicitly confirmed by Jayden. This establishes the missing-default-position defect as the operational cause for that file; the stack alone did not identify it. Preserve ID0 and reject files lacking it, even if SQLite integrity and all explicit position references pass. Successful opening is not evidence of save/reopen or console rehearsal. Empty ensembles and omitted config keys were unchanged in the successful test, so do not attribute that crash to them.

Position recall has `channel=position_id` pairs; SFANW cue11 includes `6=6,4=6,2=6,1=6`. DNAHG cue10 references position2 for multiple channels. QLab cue values are text identifiers; SFANW cue2 contains `1002`, distinct from TheatreMix number2. These observations do not prove every permissible serialization. QLab integration must not be guessed from a numbering pattern.

All three supplied files have empty cue channelProfiles, channelFX, fxMutes, snippets, channelLevels, scenes and scenePoints. Config feature enabled does not prove populated use. Do not invent profile/actor snapshot data or scene recall encoding. `profiles.data` is empty in these samples. User's earlier format notes first describe channelFX/qLabCue as confirmed and later unknown; resolve field by field, not by choosing whichever sentence is convenient.

Validator checks structural integrity and a conservative subset of semantics. It warns on multi-DCA channel membership rather than globally rejecting it: actual examples can intentionally have overlapping control-group assignments. It does not infer audible state from DCA membership without fader context, nor validate RF, routing, console firmware or application load/save. `build` intentionally rejects advanced cue fields until implemented and tested against feature-rich app-generated samples.
