Sign in

The front door is one card on the espresso ground and nothing else. It says who it is, takes an email and a password, and tells you the book will open offline.

BBinderby RVLT
the book is where you left it

••••••••••••
Email me a link instead
Stays signed in on this device, so the book opens offline.
  • One card, no rail. Nobody is signed in, so there is no navigation to show; the only red is the Sign in button.
  • The link is quiet. “Email me a link instead” is a text link, because it only appears when the server can send mail and most people never need it.
  • The note answers a worry. “Stays signed in on this device” is there because a stage manager at the tech table will not re-enter a password to open the book; it is the offline promise in one line.
  • One Kalam line, muted rather than red, under the wordmark. This is the only screen in the set that greets you, so it earns the handwriting.

Archive

Archive this show

It becomes read-only for everyone. Exports still work and nothing is deleted.

  • Departments reuse the wizard row, with the cue count and a clickable colour swatch added. The Add row sits at the end and stays dashed until it has a code.
  • Members read as a list. Role is a select on the row, the owner row says “You” instead of Remove, and the note under the invite row explains what Editor and Viewer mean in one line.
  • Archive is plain on purpose. It is reversible in spirit (read-only, nothing deleted), so the button is a normal one and the card carries the explanation.
  • “Only the owner can change these.” sits top right. On a non-owner’s screen the same page renders with the controls disabled, not hidden, so editors can still see how the show is set up.

The system

What Binder inherits, and where it differs

Everything here uses RVLT Flow’s tokens verbatim: espresso surfaces, one red, warm ink, hard offset shadows, Archivo for display, Hanken Grotesk for UI, Geist Mono for every number. Three things are Binder’s own.

The page is paper

The PDF renders white inside dark chrome, in both themes. Department colours are tuned to read as ink on white: LX amber darkens to #C9811F, SND blue to #2F6BD6. The dark-UI tints are for chrome only.

Department colour is the only colour on the page

Chrome stays monochrome plus red for the one primary action. Presence uses the person’s colour, never the department’s, and only as initials and a thin outline.

Two modes, one layout

Markup is the full shell. Calling strips it to the page. The right panel is the same component on the script, the cue list and the review, so there is one place to learn.

Three widths

One system, three layouts

Phone, under 768

Bottom tab bar inside a show; the shows list above it. Single column, cards instead of tables, the page at full width with the tags still in the margins, the panel as a bottom sheet, a “Place cue” button instead of the tool strip. 44 px targets, no hover.

Tablet, 768 to 1024

The rail keeps its icons and drops its labels. Thumbnails hide by default. The panel slides over the page from the right when something is selected. Calling mode is designed for this width first.

Desktop, over 1024

The full shell: rail with labels, thumbnails, tool strip, the right panel docked. Keyboard first: c, ], g and ⌘K do most of the work.

  • Not drawn yet: the invite email, the cue sheet print layout, Paper (light) mode on every screen, the TheatreMix import flow. They take the system as it stands.
  • Build path: adopt Flow’s registry theme and components in apps/web (shadcn + Tailwind v4), then restyle screen by screen in the order above. Accessibility work from M1 (keyboard markers, labelled controls, live regions) stays.
