A final whole-branch review (Opus) found 0 Critical and 3 Important issues; one fix wave closed them. A delta pass over the last tasks came back "Ready to deploy: Yes". An agent skill (`skills/binder`) was then written, checked against the code, and served to MCP clients.

## How it was built

- Subagent-driven development: one implementer per task (Sonnet), a per-task reviewer (Sonnet) checking spec compliance and mockup compliance, fix rounds until the review was clean, a pre-flight scan of the whole plan for contradictions before Task 1 (it produced R1 to R5).
- Parallel worktree lanes for the feature work: lane B (print, F2a to F2c), lane C (processing, F3a to F3e), lane D (pulse and keep-offline, F1a to F4b), with lane A (Tasks 12 to 14) in the main checkout. e2e runs were serialised by a lock script (`mkdir` lock that frees :3000/:5173/:4173 and sets `CI=1`; it now lives in the repo as `scripts/e2e-locked.sh`, run through `pnpm e2e`). Lanes rebased onto the restyle branch before generating migrations (R28) and were merged at quiet points.
- The approved mockups are the binding visual standard (R20). A read-only mockup audit (176 rows, classes A, B, C) fed two compliance tasks. Jayden answered the class-B scope question: build four features (F1 to F4), and leave out show phase and dates, the new-show wizard and department descriptions, and Binder as an activity actor.
- A final whole-branch review on Opus, started in parallel with Tasks 15a and 15b (R42), one fix wave in its own worktree (R43), a scoped re-review, and a delta pass over the later commits.
- Deploy: merged to main, Coolify built from `deploy/docker-compose.yml`, migrations 0016 and 0017 applied at API start, a clean-clone `docker build` of the API and web images was run first.

## Rulings

Each entry gives the decision, the reason, and the cost if wrong (where the ledger stated one). Where one ruling changes another, both entries say so.

### Design system and tokens

- **R1** (Task 2): the red-guard threshold is ΔE76 < 20, not < 10. At 10 the guard passes `#D0021B` (ΔE 13.3), the red that motivated it; 20 refuses `#D0021B`, `#B21F26` and `#E8505A` and allows coral `#CC5E2E` (25.8) and `#EF7E55` (28.7). Cost if wrong: a few reddish-oranges refused; the owner picks another. Plan, DESIGN.md section 4.3 and the spec section 6 were updated.
- **R6** (Task 1): the display font utility is Flow's `font-display` (`--font-display`), not the brief's `font-disp`. Spec section 2 requires Flow's component class names to resolve unchanged, and six Flow components use `font-display`. Cost if wrong: none.
- **R7** (Task 1): keep Flow's fixed cream tokens (`--cream`, `--cream-ink`, `--sh-cream`, `--sh-cream-press`, `--color-cream`, `--color-cream-ink`), because Task 3 copies `button.tsx` whose `cream` variant uses them. Cost: six unused lines.
- **R8** (Task 1): do not restore the accordion keyframes and animate tokens; add them with the accordion if one is ever copied. Cost: a later accordion would not animate until then.
- **R5** (Task 3): `Segmented` must expose `role="radiogroup"` with `role="radio"` items (`aria-checked`). Radix ToggleGroup with explicit roles or a native radio group are both fine; the contract is the accessible pattern. (Radix ToggleGroup's root is `role=group`, which the plan's test did not accept.) Cost: none.
- **R11** (Tasks 3, 4): `Kbd` is restyled onto Binder tokens (`font-mono text-[10.5px] text-muted bg-paper-2 border border-line-2 border-b-2 rounded-[5px] px-1.5`). The registry file uses `bg-bg-inset` and `text-fg-3`, which no theme defines, so copy-in renders an unstyled key. Cost: `Kbd` diverges from Flow's file until Flow fixes its own.
- **R12** (Task 4): rail labels are 11 px, not DESIGN section 6.2's 10 px. The 11 px floor (Flow law, a global constraint) outranks the mockup. DESIGN.md section 6.2 was corrected in Task 15a. Cost: none. (R21 applies the same floor to the mockup's 8 to 10 px labels.)
- **R20** (after Task 7, Jayden: "make sure the designs are fully compliant with the mockups"): the mockups are the binding standard for look and layout: component shapes and sizes (buttons as drawn, 10 px radius, not pills), red where the mockup puts red, copy, spacing and ordering. **Reverses** DESIGN.md section 0's earlier "registry components win" stance and the strict "one red per view" where the mockup differs. Exceptions only where the mockup needs data the app lacks (class B, surfaced to Jayden) or a floor applies (11 px text, 44 px phone targets, an accessible name an e2e relies on); each exception is listed. Process change: every remaining brief required side-by-side screenshots at the same sizes and reviewers checked mockup compliance. DESIGN.md section 0 and its decisions log were updated. Cost: copy and test churn.
- **R21** (audit class C): mockup copy wins over e2e-pinned names (for example "Export PDF" becomes "Download PDF"), with the e2e changed in the same commit. The overview's right column follows the mockup at every width (desktop: In the binder now, Needs you, Offline, links; phone: Needs you first), with DOM order equal to visual order at each width (render the card in its breakpoint slot, display-toggled, not CSS `order`). Kept exceptions: the 11 px and 44 px floors (mockup 8 to 10 px labels raised to 11), inactive phone tab labels at `--muted` for contrast, the rename pencil on show cards. DESIGN.md numbers follow the mockup (thumbnails 92 px, status bar 26 px). Cost: copy and test churn.
- **R23** (Task 9): notes and stamps match the mockup on screen and in print, keeping screen and print parity. `.note`: 2 px left bar in the department colour, 12 % colour-into-white tint, no outline on the other sides, page-ink text. `.stamp`: weight 800, letter-spacing .06em, rotate(-3deg), 1.5 px border, radius 3, 80 % white fill. Note text ink in print becomes `PAGE_INK`. This supersedes the Task 9 dispatch's "print changes only the tag-number ink". Highlight annotations are unchanged: the mockup's `.hl` is the cue-trigger underline (already per the margin-markers spec), not the highlight annotation. Cost: printed exports of notes and stamps look different from earlier exports.
- **R26** (F3a): `formatBytes` drops a trailing ".0" ("2 MB"), because the mockup's own figure is "12 MB". Cost: one formatting tweak.
- **R15** (Task 5): accept the empty-state action "Start a show" (not "New show", which would duplicate the top-bar primary's name) and the green `ok` "Active" pill (an unarchived show is not "live" in DESIGN's red sense; red stays for the primary). Cost: copy and colour tweaks.

## Known issues and open follow-ups

- **Intermittent `revisions.spec.ts` e2e** ("compare shows the cut lines as removed"): fails about one full run in three. After clicking "Compare" the "Compare versions" heading is not visible within 5 s. It passes alone. The delta review traced it to a cold Vite compile of the lazy compare chunk (the warm-up skips `/compare`); pre-existing and not a user risk. Fix: add a compare URL to the e2e warm-up and harden the test with `toPass` or a stable link and a kept trace.
- **Offline banner shifts the stage.** The banner takes layout space above `<main>`, so the document stage moves by about 56 px when the network flaps. Fix by overlaying it or debouncing it.
- **Calling-mode page counter lags.** After a keypad jump to a cue near a page boundary, the strip's page counter lags until the next scroll (seen at phone size).
- **Archived show, phone script.** A disabled "Place cue" button stays, and its explanation tooltip sits over the script text.
- **Fixed after the restyle deploy** (found while verifying the agent skill and chasing red CI; each reviewed before it shipped, the skill docs updated to match):
  - Re-anchoring moved a cue anchored to the second copy of a repeated line onto the first copy with status `ok` when the second was cut. It is now `approximate`, so it appears in the review (`649cd42`). Trade-off measured in a sweep over the Pirates script: when the copies sit in identical or edited surroundings, extra cues are flagged (17 to 35 % of survivors; the safe direction), and about 3 % of adjacent-duplicate cases (an echo line) can still stay `ok` one line away.
  - `revert_change` and `revert_batch` check the caller's rights before reporting drift, so a caller without rights gets `forbidden` and never learns what changed; `renumber_cues` reports collisions with cues it does not touch as `flagged` entries with reason `duplicate` (`4764877`).
  - OCR on the production toolchain (`cae7e7d`). CI had been red on `main` since M1 because two processing tests failed on GitHub's runner. The cause was a real production bug: OCRmyPDF older than 17 (production's Debian 12 has 14.0.1) refuses owner-restricted PDFs (exit 8), so a scanned restricted script was never OCRed, and its `--redo-ocr` rewrites content streams with exponent-form numbers (`6.1E-17`) that poppler cannot read, losing the text of a page with a quarter-turn text matrix. Fix: retry exit 8 on a `qpdf --decrypt` copy (working copy only; the original upload is untouched), and rerun a damaging `--redo-ocr` with `--skip-text`. The tests only passed on a Mac because Homebrew has OCRmyPDF 17.
- **Deferred from those reviews** (none blocking):
  - Re-anchoring: it fails open when the old text stream cannot be built, and a stored quote with no exact old copy returns "unique" (consider failing closed); an alignment-based tie-break (`diffVersionLinesBounded`) would cut the extra flags; no tests yet for three copies, adjacent copies, a highlight annotation, or accept and revert on a flagged cue; the Review panel gives no reason for the flag.
  - Revert: `reanchor:` batches still report a drift count as `conflict` before `forbidden` (by design, counted never named); a batch checks rights row by row, so an earlier editable-but-drifted row can report `conflict` before a later uneditable row reports `forbidden` (all-or-nothing holds, nothing leaks); a delete-revert whose id exists again checks only the landing layer; rights are not memoised across a large batch (performance only).
